# 开发路线图

> 这是社区实验项目的计划，不是厂商承诺。每个里程碑以真机可复现结果为完成标准。
>
> **当前实际进度：M0 之后没有任何一项通过真机验证。** 下面勾选的是"代码写了"，
> 未勾选的是"还没写或没验证"，两者都不代表可用。

## M0 — 骨架（代码已落地，2026-11-27）

- [x] Gradle / Android 工程骨架、AGPL-3.0 许可与第三方声明
- [x] 极核控制帧 / 媒体帧 / H.264 AU 封装（`ZeehoProtocol`）
- [x] RSA-2048 身份与 HUID 签名（`ZeehoIdentity`）
- [x] 网段发现（`ZeehoDiscovery`）
- [x] 四端口会话状态机骨架（`ZeehoConnection` / `ZeehoOutput`）
- [x] 来源插件接口与 CarLife / ICCOA / HiCar 槽位
- [x] CI 编译验证（GitHub Actions，含 release / debug 两种产物）
- [ ] 真机验证：无

## M1 — 极核协议闭环（不依赖手机互联协议）

目标：用静态测试图编码成 1024×480 H.264，推到仪表出画。

- [ ] 发现端口 10930 请求/应答字段与真机对齐
- [ ] 控制通道 `0x10000/0x10010` 设备资料、`HUName/HUID` 解析
- [ ] RSA 公钥 JSON 字段名与打包格式真机校正
- [ ] 媒体通道 `0x10/0x11` 尺寸（1024×480）与编码协商
- [ ] 视频通道 `0x72` 逐帧拉取、首帧 8 字节前缀确认
- [ ] 心跳 `0x70000000`、停止与重新进入投屏
- [ ] 真机日志与抓包归档（脱敏）

**验收**：仪表稳定显示测试图 ≥ 5 分钟，无掉线。
**状态**：代码已写，一次都没跑过。

## M2 — OPPO Car+ 接通（阶段一主线）

- [x] 移植 CarNine `CarLifeLink` 七端口握手与 H.264 收流（代码层面）
- [x] `CarLifePhoneSource` 输出 `VideoFrame` 到 `CastEngine`
- [x] 本地预览旁路（`H264Decoder` / `PreviewView`），不依赖仪表
- [x] Car+ 组件枚举与逐个拉起试探（`CarAppLauncher`）
- [ ] 确认 Car+ 能否被拉进 CarLife 模式、7 端口是否真的在 127.0.0.1 监听
- [ ] 848×480 → 1024×480 转码兜底（MediaCodec）
- [ ] 帧率 25 FPS / 码率 2500 kbps 对齐
- [ ] Wi-Fi Direct 选网、前台服务保活
- [ ] 锁屏 / 切后台 / 来电中断后恢复

**验收**：OPPO 手机导航画面实时投到仪表，延迟可接受，连续 30 分钟不崩。
**状态**：全部未验证；连"端口会不会开"都还是未知。
