# 真机测试计划

没有硬件就无法完成协议校正。本文件列出需要验证的环节与需要回传的信息。

## 测试设备

| 项目 | 需要记录 |
| --- | --- |
| 仪表 | 型号（AE4 MAX2+ 6.2 寸）、固件版本、屏幕分辨率 |
| 手机 | 品牌型号、系统版本、ColorOS 版本 |
| 手机 App | Car+ 版本、本项目 APK 版本 |
| 网络 | 普通 Wi-Fi 还是 Wi-Fi Direct、手机与仪表 IP、路由器型号 |

## 阶段一：极核协议闭环（M1）

1. 手机连接仪表 Wi-Fi，在仪表上手动开启投屏。
2. 启动 App，确认日志中出现发现端口 10930 的广播与应答。
3. 确认仪表反向连回 10922 / 10711 / 10710。
4. 记录控制通道 `0x10010` 返回的 `HUName` / `HUID` **结构**（值请脱敏）。
5. 记录媒体通道 `0x10` 上报的宽高与编码字段。
6. 推送静态测试图，确认出画与首帧格式。
7. 连续运行 5 分钟，记录心跳与断线情况。

## 阶段二：OPPO Car+ 接通（M2）

1. 手机打开 Car+ 并进入导航。
2. 确认 CarLife 七端口握手成功，收到 H.264 流。
3. 确认转发到仪表后分辨率与帧率正确。
4. 测试：锁屏、切后台、来电、Wi-Fi 切换、退出投屏后重进。
5. 连续运行 30 分钟，记录崩溃与内存增长。

## 需要回传的材料

- `adb logcat` 日志（请用 `adb logcat -c` 清空后复现问题再抓取）。
- 投屏建立阶段的 TCP/UDP 抓包（pcap），**请脱敏**：
  - 删除或替换 `HUID`、phoneID、手机号、Wi-Fi 密码、公钥以外的敏感字段；
  - 不要提交任何私钥。
- 问题复现步骤与期望/实际行为。

## 脱敏清单

必须脱敏：HUID 具体值、IMEI、手机号、MAC 地址、Wi-Fi SSID/密码、真实姓名、定位坐标。
可以保留：命令码、帧结构、字段顺序、长度、端口、时序、错误码。

## 已知无法通过软件解决的情况

- 仪表固件不接受第三方身份握手 → 需要厂商授权，项目无法绕过。
- 2026 款 AE4i Pro / AE6 使用另一套通道与分辨率 → 不在当前实现范围。
- 仪表触摸反控 → 老协议中 `0x20` 明确不执行。
